МОБИЛЬНАЯ ВЕРСИЯ — ГЛАВНЫЙ ПРИОРИТЕТ

Сайт в первую очередь будут просматривать со смартфонов.

Используй подход mobile-first:
сначала спроектируй интерфейс для мобильного экрана, затем расширяй его для планшетов и desktop.

Основной целевой размер:
- 390 × 844 px (современный смартфон)

Также обязательно проверь:
- 360 px
- 390 px
- 430 px
- 768 px
- 1024 px
- 1440 px

Мобильная версия не должна выглядеть как просто уменьшенная desktop-версия.
Она должна иметь собственную хорошо продуманную вертикальную композицию.

МОБИЛЬНАЯ КОМПОЗИЦИЯ

1. HERO

На телефоне главный экран должен выглядеть эффектно сразу после открытия сайта.

Изображение main должно занимать всю ширину экрана.
Заголовок «Арка Кокошник» размести поверх изображения.

Следи за тем, чтобы основная архитектура на фотографии не обрезалась неудачно.
При необходимости используй object-position отдельно для мобильной версии.

Высота hero на телефоне должна учитывать маленькие экраны и современные мобильные браузеры.
Не допускай ситуации, когда заголовок или важная часть изображения оказываются за пределами видимой области.


2. О ПРОЕКТЕ

На desktop:
текст слева, схема справа.

На телефоне:
текст
↓
схема

Текст должен легко читаться без масштабирования страницы.

Схема должна занимать доступную ширину экрана и оставаться разборчивой.


3. ТЕХНОЛОГИЯ

На desktop:
текст слева, изображение справа.

На телефоне:
заголовок «Технология»
↓
текст
↓
изображение технологии

Изображение должно занимать практически всю доступную ширину.


4. ПРОЕКТНАЯ КОМАНДА

На телефоне все категории команды располагаются вертикально.

Не делай маленькие карточки в несколько колонок.

Структура:

Проектная команда

Архитекторы
Веревкина Ирина
Лиханова Елена

Конструкторы
Жаныбеков Жамшитбек
Сарычев Антон
Шариков Тимофей

Технический оператор
Иглевский Иван

ИТ-специалисты
Клыжко Владимир
Майбах Артем

Между категориями должны быть хорошо заметные отступы.


5. FOOTER

На мобильном экране логотипы должны аккуратно переноситься и не становиться слишком маленькими.

Блок курса:

«Повышение квалификации
„Аддитивные технологии в архитектуре и строительстве“»

должен быть удобен для нажатия пальцем.

QR-код на мобильной версии оставь, но он не должен занимать слишком много места.
При этом QR-код должен оставаться достаточно большим для корректного сканирования с другого устройства.


МОБИЛЬНАЯ ТИПОГРАФИКА

Используй CSS clamp() для адаптивных размеров.

Не делай основной текст слишком мелким.
На смартфоне основной текст должен быть примерно 16–18 px с комфортным межстрочным интервалом.

Крупные заголовки должны масштабироваться в зависимости от ширины экрана.

Не допускай слишком длинных строк текста.
На desktop ограничивай ширину текстовых блоков для удобства чтения.


МОБИЛЬНЫЕ ОТСТУПЫ

Используй единообразную систему отступов.

На телефоне контент не должен прилипать к краям экрана.
Оставь комфортные боковые поля примерно 20–24 px.

Между крупными секциями оставляй достаточно воздуха, но не делай вертикальные отступы настолько большими, чтобы пользователю приходилось долго прокручивать пустое пространство.


TOUCH UX

Все интерактивные элементы должны быть удобны для нажатия пальцем.

Минимальная удобная область нажатия — около 44 × 44 px.

Не используй интерфейс, функциональность которого зависит от hover.

Все важные элементы должны нормально работать через touch.


ПРОИЗВОДИТЕЛЬНОСТЬ НА ТЕЛЕФОНЕ

Это особенно важно.

Оптимизируй загрузку изображений для мобильных устройств.

- Не загружай неоправданно огромные изображения, если они отображаются маленькими.
- Используй loading="lazy" для изображений ниже первого экрана.
- Главное hero-изображение не должно использовать lazy loading.
- По возможности используй responsive images через srcset/sizes, если в проекте доступны изображения разных размеров.
- Указывай width/height или aspect-ratio для изображений, чтобы страница не прыгала во время загрузки.
- Минимизируй JavaScript.
- Не подключай тяжёлые библиотеки.
- Не используй видео или тяжёлые эффекты без необходимости.

Страница должна быстро открываться через мобильный интернет.


АНИМАЦИИ

На телефоне анимации должны быть очень лёгкими.

Используй только ненавязчивое появление контента при прокрутке.

Не используй тяжёлый parallax, сложные scroll-анимации или эффекты, которые могут тормозить страницу.

Учитывай prefers-reduced-motion и отключай необязательные анимации для пользователей, которые выбрали уменьшение движения.


БЕЗОПАСНЫЕ ОБЛАСТИ

Учти safe-area современных смартфонов.

Контент не должен конфликтовать с вырезами экрана или системными элементами браузера.

Используй современные единицы viewport (svh/dvh), где это имеет смысл.


ФИНАЛЬНАЯ ПРОВЕРКА

Перед завершением обязательно проверь страницу в мобильном viewport 390 × 844 px.

Убедись, что:
- нет горизонтального скролла;
- текст нигде не обрезается;
- изображения не деформируются;
- важные части фотографий не обрезаны;
- схема остаётся читаемой;
- размер текста комфортен без zoom;
- ссылка на курс легко нажимается;
- QR-код отображается корректно;
- нет элементов, требующих hover;
- нет layout shift при загрузке изображений;
- сайт выглядит как специально разработанный мобильный сайт, а не уменьшенная desktop-страница.

После этого проверь desktop-версию и убедись, что расширение layout для больших экранов не ломает мобильную версию.
